# Proposed phase-control circuit — not implemented or qualified

The lead proposed local precharge control `PC = enable OR OR(actual final WL[63:0])`, where high PC disables PMOS precharge. The intent is for rising enable to disable precharge promptly, and for PC to remain high after enable falls until the actual decoder outputs fall. This is an acyclic engineering proposal, not measured nonoverlap behavior.

The GF180 library provides OR4 and OR2 primitives. A four-input reduction tree takes 16+4+1 OR4 cells plus the final OR2. That cell count appears physically plausible inside the existing 120×120 µm decoder outline, but no placement, route, DRC, LVS or timing has been run for this variant. Instantiate explicit protected primitives and audit the final mapped topology: pure Boolean synthesis can simplify the delay-dependent feedback-of-output logic back to enable and remove the intended protection. Preserve existing decoder artifacts; create a separate named variant if authorized later.

Monitoring the driver pin does not monitor the far end of a resistive distributed wordline. Also, Boolean low at the OR input is not proof that every access NMOS is already below its conducting threshold. Precharge PMOS turn-on and wordline NMOS turn-off thresholds can overlap. Therefore verify falling-edge nonoverlap with extracted distributed WL/PC resistance and capacitance, real output drivers, actual transistor thresholds and matched PVT. On rising enable, the direct path must disable every precharge device before the earliest selected wordline can conduct. OR-tree glitches, bank/address changes, reset and abort also require tests.

A buffered enable could be a candidate `capture_gate`, but it must demonstrably close all output latches before the earliest possible precharge corruption and still permit sufficient read/mux/book-map settling before W2b representative capture. No such guarantee follows from the schematic equation. External capture-gate distribution across ten latch strips is another physical timing obligation.

This circuit does not resolve the W2b `step_enable` late-assertion hazard: ARRAY-PORT can request and capture within arbitrarily little time unless its request/ready or setup contract changes. Freeze that interface first; then test all stalls, restarts, bank/row transitions and reset cases against the real macro. Whole-macro timing and area remain null until an electrically connected implementation is measured.
