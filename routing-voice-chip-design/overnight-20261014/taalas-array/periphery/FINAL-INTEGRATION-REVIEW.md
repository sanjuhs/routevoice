# Independent W5 integration review

The checked artifacts do not yet form a W2b-compatible whole macro. The current joined tile contains real cells, analog readout and physical joins, while the routed digital decoders/mux are separate. The following findings concern the current saved sources and reports; proposed connections below have not been routed or electrically qualified.

## Evidence that is actually present

`base/geometry.json` reports all 1,638,400 programmed bit positions read back from reopened GDS with zero mismatches. Base tile0 has 81,920 exact extracted devices and a qualified Netgen unique match after bijective name normalization. The twenty base islands pass selected hierarchical DRC, but `base/composition-audit.json` explicitly says `physically_interconnected:false`; there is no top-level service or LVS credit from that placement.

`integrated/readout-tile0.gds` is one real 64×320 tile with 1,280 physical receivers and real bitline-to-receiver routes. Its saved full-tile result matches all 87,040 device tuples/W/L and reports an independent Netgen unique match after bijective label normalization. Its selected DRC count is zero. GDS bounds are 4,669.7×220 µm; the LEF rounds the width to 4,670 µm and geometrically checks all 1,347 pins. This is the 20,480-selection tile0, not twenty electrically composed real-image tiles.

The physically joined bank0 timing result includes real join capacitance and passes the exercised TT/SS protocols. Its SS 2.97 V 125°C latest sampled settling is 4.390 ns after ideal wordline evaluation begins in the 20 ns case. Its actual tested region is rows0–63, columns0–31. It is not the earlier maximum-population bank and is not a full-array worst-case bound. Ideal drivers, missing distributed resistance, local output loads and sampled coverage remain explicit limits.

The final periphery directory `handoff-v2/` contains three routed blocks. Each has selected KLayout DRC0, Magic DRC0, Netgen LVS0 and meaningful routed-gate-netlist functional checks. Row decoder and mux slow-corner timing/electrical failures remain. None is connected into the readout tile.

## Critical latch correction

The earlier periphery claim that W2b already implements1,280 physical index-capture bits was wrong; it has been corrected and its old versions preserved. `index_latch` is never read and is absent from the synthesized ARRAY-PORT netlist. Actual live state is `representative_latch_0..319`, loaded from combinational book lookups using `frozen_index_bits` and `codebook_row_domain`.

Consequently the macro must satisfy the path through **its readout, bank mux and W2b book lookup before representative capture**. A raw-index latch count cannot be inferred from the dead RTL declaration. A separate physical128-bit transparent latch strip with explicit `capture_gate` is now complete: selected KLayout DRC0, Magic DRC0, Netgen LVS0 and1,411 routed gate functional checks. Ten-copy composition and gate control remain unimplemented. Its gate-control protocol is not implied by the current read-enable signal. See `LATCH-ERRATUM.md`, `LATCH-RESULTS.md` and `latch-results.json`.

## Protocol changes or guarantees required

1. Implement a physical nonoverlap sequencer. Begin with every wordline low and precharge asserted; release precharge, wait for its distributed settling, then enable the addressed wordline. Open/settle the output latches only after the selected bank/mux value is valid. Close them before precharge can disturb their inputs. Deassert wordlines and allow their worst distributed fall delay before asserting precharge. Address changes and bank changes must occur only with wordlines safely off. A real gate/driver circuit and extracted timing are required, not independently prescribed SPICE voltage-source waveforms.
2. Resolve the `step_enable` hazard. W2b currently uses `array_read_enable = (state==INDEX && step_enable)` and captures whenever `state==INDEX && step_enable` at the next rising edge. Reasserting step_enable shortly before that edge permits capture after arbitrarily little analog read time. The RTL functional ROM does not expose this failure. Either separate the physical read request from step_enable, retain a request/valid state with qualified completion, or impose and verify an explicit full-read-time setup contract on the external controller. An explicit array-ready handshake is the clearest general solution; changing this requires W2b contract/RTL/tests to agree.
3. Coordinate macro reset/abort and startup. A transparent latch without reset may safely remain unknown only if no consumer can capture before a completed first read. A reset during evaluate or while a result is held must return the phase controller to a known precharged state and retire any old request before a new row is accepted.
4. Keep capture timing explicit. A transparent latch can pass data within the existing INDEX cycle, but its close timing, hold isolation and added D-to-Q delay still count. An extra edge-triggered register changes latency unless W2b's schedule is deliberately modified. Do not silently make either change.

There are1,280 index reads in4,160 integer cycles. Those counts are distinct. A longer physical read cycle or ready stalls changes the achieved projection schedule and must be replayed with the actual macro protocol.

## Concrete geometry findings

The current joined tile **already shorts corresponding wordlines across all ten subbanks** using common Metal3. Each of64 rails extends about4,315.48 µm and drives1,280 access gates. PC is also a common Metal3 rail extending to4,669.7 µm and drives1,280 precharge transistors. The new long shared rails are absent from the single-bank SPICE qualification. The100 fF load used for each standalone decoder output is not evidence that it can drive this tile. Likewise, the prior200-decoder area ledger describes separately decoded subbanks, not this common-wordline topology.

Do not attach ten complete decoder output banks to the same already-shared wordlines as if they were independent nets. Choose one intentional distribution architecture: one decoder per tile with sufficiently characterized global drivers, or segmented local wordlines driven by explicit distributed repeaters. Segmenting requires changing physical nets and the LVS reference. In either case characterize the full WL/PC wire resistance, capacitance and driver supply currents.

Decoder-to-tile port spacing itself is not an obvious geometric blocker. Final decoder WL0..63 appear monotonically on its east edge at y23.80..94.36 µm, pitch1.12 µm. Tile WL0..63 are monotonically on its west edge at y112.90..216.22 µm, minimum pitch1.44 µm. An R0 decoder at y89.10 µm aligns WL0; a proposed64 µm horizontal channel accommodates64 staggered Metal2 columns at0.66 µm pitch (42.24 µm total), with Metal3 horizontal legs and legal0.38 µm via landings. Reverse-order routing columns avoid overlaps between source-side and target-side legs. This is a constructive routing proposal requiring DRC/LVS; it is not a measured connection or an electrical qualification of the4.3 mm rails.

Mux integration is substantially harder. The routed mux has2,560 data-input pins scattered over all four sides:799 south,456 north,666 east and639 west. Even bank0's128 pins are split42/21/39/26 over those sides. Adjacent pins reach0.56 µm pitch. The readout tile's output pins are on its south edge at3.5 µm pitch within each128-bit subbank. Thus a single monotonic128-wire comb cannot directly connect one readout bank to the mux; a real escape/redistribution route is needed. At0.56 µm pitch, putting0.38 µm via landings on every adjacent pin at one common coordinate would leave only0.18 µm spacing, below the0.28 µm intermediate-metal rule used by these generators. Extend on the same metal and stagger/spread transitions before inserting vias. Pin legality within the isolated mux does not qualify its external escapes.

Twenty readout tiles feeding ten mux128 instances create25,600 separate bank-data nets. Those cannot be collapsed into a shared wired bus: the existing receiver outputs are ordinary CMOS inverter outputs. The selected mux hierarchy, placement, channel widths, all bank enables, supplies and global data wires must be routed and extracted. Physically repeating the large readout tile also requires twenty distinct real mask images; only tile0 currently has joined-readout proof.

## Timing and handoff requirements

The row decoder's extracted worst setup slack is−0.806 ns with11 maximum-RC slow-corner slew violations. Mux128 is−10.582 ns with303 slew and2 capacitance violations at its worst corner. Bank decode passes its standalone assumptions. These results use SS3.00 V Liberty, not SS2.97 V transistor simulation. They cannot simply be concatenated with the sampled ideal-driver array settling result and called signed-off timing.

Required next evidence: freeze a real request/phase/capture contract; route the chosen WL/PC driver distribution, bank enables, data selection and output-latch gates; extract distributed RC and receiver loads; characterize the complete read/capture path including the W2b book lookup at matched corners; retest stalls/reset/invalid rows and bank transitions; program/reopen/readback all twenty integrated tiles; run full composition DRC/LVS and PDN continuity checks; then generate a complete macro LEF/GDS plus timing/power views. The present LEF is explicitly a partial tile and has no valid complete-read Liberty model.

The current4,670×220 µm readout LEF declares full-layer obstructions while its pins lie on actual boundary metal. Verify the eventual router can access each intended boundary pin and every PDN landing in a small integration test. Metal containment alone is not a routing-access or supply-integrity proof. Long narrow common power rails also need actual drop/EM analysis before full-array current or energy claims.

No new large flow was run for this review. `review-port-geometry.json` records the directly inspected pin coordinates and distributions. The output-latch construction is a subsequent separately authorized task.
