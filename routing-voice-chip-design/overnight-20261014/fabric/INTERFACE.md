# Projection interface and measurement scope

The three modules share active-low synchronous `rst_n`, `clk`, `start`, `x[8:0]`, `x_valid`, `x_ready`, `busy`, `done`, `row_addr[8:0]`, `asum[17:0]`, and the combinational result read port `rd_addr[8:0]` / `rd_data[26:0]`. `x`, `asum`, and `rd_data` are signed. Coefficients are unsigned UINT8.

Pulse `start` while idle. At that edge the accumulators, sum and row counter clear; `busy` and `x_ready` become high. A later rising edge with `x_valid && x_ready` accepts the activation for the current `row_addr`. Stalls leave the row counter unchanged. A start while busy is ignored. After the last activation, `x_ready` drops; the registered product is accumulated one edge later, when `done` pulses and `busy` drops. Outputs remain readable until the next accepted start. Read addresses 320–511 return zero. Values read while busy are partial accumulations.

For V2, supply `idx_row[n*4 +: 4]` and the 16-entry book `book_row[n*128 +: 128]` for every output n, aligned with the current row. Entry j is `book_row[n*128+j*8 +: 8]`. The group is `row_addr[8:6]`. The benchmark's external array model supplies these combinationally and keeps them valid at the activation acceptance edge. It does not model custom-array access delay, electrical loading, read control, peripheral area or energy. Those costs must be added and the interface timing requalified when a physical array exists.

The full modules accept 320 activations; the slice accepts only the first 64 rows from image 0. Accepted-start-to-done latency is 321 or 65 clocks without stalls. The next start can be accepted on the following clock: minimum initiation interval 322 or 66 clocks if results need no serial readout. Reading all results at one per clock adds 320 clocks; full start-to-readout-completion is 641 clocks and earliest subsequent start is 642. The power testbench adds two idle clocks between traced vectors, making its workload 643 clocks/vector for full variants and 387 for the slice. The reported power therefore includes compute, readout and those idle intervals, rather than continuous back-to-back compute.

Exact arithmetic widths are independent: 4-bit index, 8-bit representative, 9-bit activation, 13-bit shared nibble product, 17-bit reconstructed product, 27-bit accumulator, and 18-bit activation sum. No quantization beyond the supplied UINT8 source values is introduced. The raw product is `sum(x[k]*W[k,n])`. Downstream weight zero-point correction can use `asum`; source affine scales/zero points, bias, attention, writable state and full recognition are outside this primitive.

V1 synthesis is allowed to optimize frozen indices/books into arbitrary equivalent standard-cell logic. Thus the physical result would measure this compiler/RTL implementation, not guarantee preservation of a literal transistor-array topology. V2 measures a dynamically selected datapath with all books supplied through ports; it is not an apples-to-apples subtraction baseline for the one-group V1 slice, whose constants enable substantially different optimization.

The V2 block-level physical experiment assigns its 42,240 index/book input bits to boundary pins across Metal1–5. This is a test configuration for an internal array interface, not a chip pad ring. The resulting footprint and wire timing depend on that pin placement; an integrated custom array may require a different floorplan and characterization. Initial input/output delay constraints are 4 ns at a 20 ns clock; slower continuations explicitly scale these delays with the target period. They are constraints, not measured custom-array access times.
